## 安装与配置

四次 APT 事务合计新增 323 个软件包，0 升级、0 删除。没有更新 Linux、GRUB 或
U-Boot，已有 NetworkManager 和 UPower 保留。主要组件版本为 Phosh
`0.46.0-3+deb13u1`、Phoc `0.46.0-1`、Squeekboard `1.43.1-1`。

有网络的手机可复现：

```sh
sudo apt-get install --no-install-recommends \
  phosh phoc squeekboard gnome-session-bin gnome-session-common \
  gnome-settings-daemon phosh-mobile-tweaks feedbackd xdg-desktop-portal-phosh \
  phosh-mobile-settings gnome-console xwayland \
  libglib2.0-bin polkitd rtkit gnome-backgrounds \
  gnome-control-center gnome-keyring libpam-gnome-keyring gnome-snapshot
```

`libglib2.0-bin` 提供 gnome-session 启动脚本直接调用的 `gsettings`。
`polkitd` 为桌面网络操作和电源事件接管提供授权服务，不添加自定义放权规则。
首次会话启动时尚未安装这两个组件，日志有对应错误。重启后的 Phosh 已取得
`handle-power-key` 和 `sleep` inhibitor；原先的授权错误不再出现在该启动记录中。
RTKit 补齐 PipeWire 调度服务，壁纸包提供 Phosh 默认主题引用的资源。

`/etc/lightdm/lightdm.conf.d/60-raphael-phosh.conf`：

```ini
[Seat:*]
user-session=phosh
```

`/home/lijian/.dmrc` 的 `Session` 和 GTK greeter 缓存的 `last-session` 均为 `phosh`。
第一次切换仍进入 XFCE，是 greeter 的 `last-session=lightdm-xsession` 缓存覆盖了
新默认会话；修正缓存并重启 LightDM 后，已实测选择 Phosh。
备份位于 `/var/backups/raphael/desktop-before-phosh-20260905/`。

登录界面保留 Onboard，XFCE 的用户自启动项限制为 `OnlyShowIn=XFCE;`。
Phosh 会话使用 Squeekboard，未强制修改 Phoc 输出缩放。原生手机终端为 Console，
Xwayland 为已有 X11 应用提供兼容环境。

## 电源键后备策略

首轮 Phosh 会话未取得按键接管权限，用户短按电源键后系统关机。上一次启动日志记录
`Power key pressed short.` → `Powering off...` → 正常停服务，与用户操作一致。
补齐 polkitd 并重新登录后，Phosh 和 GNOME 都已取得电源键 inhibitor。

另配置 `/etc/systemd/logind.conf.d/60-raphael-power-key.conf`：

```ini
[Login]
HandlePowerKey=lock
```

通过 `systemctl reload systemd-logind` 在线生效；D-Bus 属性实读为 `lock`，
不终止当前桌面。如果桌面未接管按键，短按的系统后备动作是锁屏；桌面取得 inhibitor
时由桌面处理。[配置语义](https://manpages.debian.org/trixie/systemd/logind.conf.5.en.html)
用户已确认短按锁屏、唤醒与再次解锁正常。

## Wi-Fi 与桌面外设测试

已补齐 GNOME Control Center `48.4`、GNOME Keyring `48.0` 和 PAM 集成。
此前 NM 日志记录 `No agents were available for this request`；补齐组件并打开系统
Wi-Fi 设置后，用户完成连接，实读 `wlan0=connected`，已取得 DHCP 地址。
GNOME Keyring 的 `org.freedesktop.secrets` 服务运行。Phosh 自带网络密码代理，
不能仅凭缺 keyring 将其注册失败根因写死；快捷面板连接全新网络的弹窗仍需单独复测。

相机应用为 `gnome-snapshot 48.0.1`，命令名 `snapshot`，实际以 `lijian` 启动并调用
Camera portal；用户照片确认界面为 `No Camera Found`。系统没有 `/dev/video*` 或 `/dev/media*`，当前内核 CAMSS 匹配表
也没有 SM8150；应用安装不能补齐采集链，物理预览仍未通过。没有保存照片或录像。

音频实读 `/proc/asound/cards` 为空，PipeWire 只有 Dummy Output。控制 DTB 的
`qcom,sm8150-sndcard` 不匹配 `msm-snd-sdm845` 驱动；源码候选 DTS 已有
`qcom,sdm845-sndcard` fallback，但候选 DTB 尚未部署。一次运行期 driver_override
测试返回 I/O error，仍无声卡；测试结束已清空 override 并卸载 `snd_soc_sdm845`。
这证明单独越过匹配条件仍不足以完成声卡注册，进一步的 probe 失败原因待查。
没有把 Dummy Output 的播放当成扬声器测试成功。

桌面操作期间还记录了 GPU translation fault 和部分触摸帧 checksum error；
现阶段可用于继续开发，不能据此宣称全外设或长时间稳定性验收完成。
